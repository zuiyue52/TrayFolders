# 代码结构与开发约定

## 宿主程序

`Program.cs` 只负责入口和单实例。`Services/CommandLine.cs` 处理诊断命令，`Interop/NativeEngineTransport.cs` 封装与原生 DLL 的调用。

主窗口按职责拆为同一个 partial class：

- `UI/MainForm.cs`：窗口生命周期、托盘菜单、启停按钮与状态消息。
- `UI/MainForm.Layout.cs`：控件与布局，保留单行 TableLayoutPanel 的显式行高约束。
- `UI/MainForm.Folders.cs`：新建、删除、排序、规则保存、选择加入及移出。
- `UI/MainForm.Inventory.cs`：列表内容与选择状态刷新。
- `UI/MainForm.Settings.cs`：设置选项卡和状态刷新时机。
- `UI/MainForm.Compatibility.cs`：系统适配页、异步准备、取消和界面结构验证状态。
- `UI/StartupSettingsPanel.cs`：启动选项、草稿保留、保存及错误提示。
- `UI/UiFactory.cs`：主窗口和选择对话框共用的控件创建函数。
- `UI/DisplayLayout.cs`：窗口工作区约束、随 DPI 缩放的标题和可滚动页面。

`Services/EngineController.cs` 管理连接状态和 Explorer 重启后的重连；通过 `IEngineTransport` 可在不接触 Explorer 的情况下测试。`InventoryReader.cs` 读取名单和检测文件变更；`SettingsStore.cs` 保存配置与归属；`CompatibilityService.cs` 识别已加载组件并调度独立符号解析器；`PlatformCompatibility.cs` 检查旧模组冲突。`Domain` 包含文件夹、图标模型及命令枚举。

## 原生核心

原生 DLL 以 `src/native/engine.cpp` 为编译入口，按固定顺序包含以下实现片段；`symbol_resolver.cpp` 单独编译为 `TrayFolders.Symbols.exe`：

| 文件 | 职责 |
| --- | --- |
| `configuration.inc` | 读取配置、解析符号、匹配规则 |
| `icon_reader.inc` | 托盘内部接口与图标名称读取 |
| `overflow_state.inc` | 面板状态、集合定位、手动归属 |
| `folder_tiles.inc` | 文件夹图块、缩略图及符号 |
| `display_items.inc` | 分组重建、导航、图标名单快照 |
| `overflow_binding.inc` | 附加、解绑及配置应用 |
| `shell_hooks.inc` | 展开和布局挂钩 |
| `thread_dispatch.inc` | 托盘 UI 线程调度 |
| `module_adapter.inc` | 系统模块版本和符号适配 |
| `drag_drop.inc` | 原生鼠标拖动归属 |
| `lifecycle.inc` | 控制命令、启用、停止与 DLL 生命周期 |

原生 DLL 保持一个编译单元，保留原有定义顺序和初始化顺序。`.inc` 文件不是独立编译单元；后续需要调整接口时再逐项独立编译，避免一次改动跨线程状态和回调寿命。

原生 DLL 只向 Shell_TrayWnd 所在线程安装控制消息挂钩，校验系统模块时间戳、镜像大小和 PDB GUID。0.4.0 改为由独立符号解析器按当前组件 SHA256 缓存动态适配数据。停止时恢复原 ItemsSource、移除鼠标挂钩并禁用函数挂钩；DLL 保留到 Explorer 退出，以保护可能仍在执行的回调。

## 数据和命令

- `settings.ini` 保存文件夹稳定 ID、名称、显示符号和规则。
- `assignments.ini` 保存拖动及选择分配；优先于规则，`@root` 表示显式移出。
- 手动键使用程序名的小写 UTF-16 十六进制编码；Explorer 系统图标使用提示名称区分。
- `icons.tsv` 为 UTF-8，共五列：程序名、悬停文字、可访问名称、文件夹索引、稳定文件夹 ID。工作线程写入，宿主每 750 毫秒检查变更。
- 自动刷新使用已保存的规则，不会覆盖正在编辑的名称和规则草稿。

| 命令值 | 含义 |
| --- | --- |
| 1 | 启用 |
| 2 | 重读设置和归属 |
| 3 | 恢复原始托盘并停用 |
| 4 | 查询状态 |
| 5 | 重读当前图标并写出快照 |
| 6 | 查询界面结构验证状态 |

返回 1 为活动状态，0 为停用，负数为失败。刷新返回 2 仅表示需要先展开一次面板，不改变核心启用状态。命令 6 返回 1 表示界面验证通过，2 表示等待首次展开，-13 表示结构校验失败，0 表示已停用。

## 构建、验证和发布

`project.psd1` 集中管理应用版本及原生 DLL 名称。构建时生成 `build/generated/BuildInfo.g.cs`，同时用于版本资源和 DllImport，不手工维护重复版本号。

Git 只跟踪源码、测试、构建脚本、默认配置、资源和文档。`build`、`dist`、`release` 及本机快捷方式由 `.gitignore` 排除；实际图标名单、个人配置和诊断结果保留在本机目录。默认 INI 配置使用带 BOM 的 UTF-16 LE，供 Windows 配置 API 读取中文内容；编辑时遵循 `.editorconfig` 中的编码设置。

- `Build.ps1`：输出 `build/bin`，不写入 `dist`。
- `Test.ps1`：构建独立测试 EXE，结果写入 `build/test-results`；正式程序不包含测试入口或测试类型。
- `Test.ps1 -IncludeReleaseChecks`：额外验证升级保留个人配置、拒绝同名不同原生 DLL、发布包默认配置和文件哈希。
- `Test-Adaptation.ps1`：独立解析系统模块并验证适配数据、内存映射和离线缓存；不安装 Explorer 挂钩。
- `Update-Local.ps1`：备份旧程序、符号解析器与配置，更新程序及运行时配置，已有个人配置保持原字节内容。
- `Package.ps1`：按白名单分别生成源码包和便携包，每包附逐文件 SHA256 清单，并输出 ZIP 校验文件；公开版说明见 [BUILD.md](BUILD.md)。

C# 测试覆盖核心状态转换、重连、停止失败保留连接、归属优先级、文件夹重排、新建/删除/加入操作、自动刷新、未保存输入、不同尺寸布局和程序图标。测试窗口在屏幕外渲染，不安装 Explorer 挂钩。

诊断命令包括 `--prepare`、`--probe`、`--compat-status`、`--status`、`--refresh`、`--stop`，结果写入程序目录的 `command-result.txt`。`--prepare` 允许下载符号，`--probe` 仅使用缓存；二者均不安装挂钩。旧 `--self-test` 已迁至独立测试脚本。

## 0.3.1 静默启动

`StartupOptions` 解析 `--silent` 和 `--no-start`；`TrayApplicationContext` 独立持有窗口，避免 WinForms 消息循环自动显示主窗口。隐藏窗口仍创建句柄以处理退出和会话结束，托盘菜单可以按需显示窗口。

自动启用由计时器调度，不依赖窗口首次显示事件。`StartupRetry` 对任务栏缺失、托盘模块尚未加载和响应超时进行有限重试；不兼容组件或旧模组冲突等永久错误不会反复尝试。手动停用与退出会取消待执行的启动重试。

`Set-Autostart.ps1` 只配置当前用户的 `Run\TrayFolders` 项，命令带 `--silent`。不需要服务或管理员权限。测试额外覆盖无窗口闪现、之后显示设置、隐藏窗口退出、启动参数和重试状态。

## 0.3.2 应用内启动设置

`Services/StartupPreferences.cs` 封装当前用户的启动项。`HKCU\Software\Microsoft\Windows\CurrentVersion\Run\TrayFolders` 是实际注册状态；`HKCU\Software\TrayFolders\SilentAutostart` 只保存关闭自启动后的静默偏好。有启动项时，以命令中的 `--silent` 为准。保存开启时只清除本程序的 `StartupApproved\Run` 禁用记录，不修改其他程序。

`IStartupPreferencesStore` 用于界面测试注入。打开设置页只读取状态，必须点击“保存启动设置”才写入；普通刷新保留草稿，“刷新状态”明确重新载入。读取失败会禁用保存，避免把未知状态覆盖为默认值。现有主窗口隐藏与分组核心逻辑保持不变。

`StartupSettingsTests` 验证控件行为、未保存修改、保存失败与读取恢复。注册表集成检查仅在 `HKCU\Software\TrayFolders.Tests\<随机 ID>` 中模拟启动目录，并在结束时删除该随机测试分支，不接触真实启动项。测试覆盖含中文与空格的路径引号、开关读写、Windows 禁用状态、旧位置修正及其他程序项保留。页面另渲染默认、最小和放大尺寸供检查。

## 0.4.0 动态适配

- `Services/CompatibilityService.cs`：识别 Shell_TrayWnd 对应 Explorer 进程里实际加载的系统模块，优先 SystemTray.dll，回退 Taskbar.View.dll；后台启动匹配符号解析器，支持取消、4 分钟超时和进度报告。
- `UI/MainForm.Compatibility.cs`：系统适配页、异步启用、首次展开后的结构验证状态。启动期间可停止；登录时网络下载失败最多重试 3 次，间隔 30 秒。
- `native/symbol_catalog.h`：所需函数、GUID 与虚函数表的完整名称及类型；不包含任何固定 RVA。名称仅移除空白与 __ptr64 修饰后比较，保留函数参数及返回值签名。
- `native/pe_image.h`：有边界检查的 PE/RSDS 识别与 SHA256。
- `native/symbol_resolver.cpp`：独立 x64 控制台辅助程序，由宿主隐藏启动。WinHTTP 从微软符号服务器下载，检查 PDB 完整长度，再用系统 DbgHelp 精确匹配 GUID/Age、解析符号。DbgHelp 不使用环境符号路径，不进入 Explorer。父进程退出时辅助进程退出。
- `native/adaptation_profile.h`：版本化定长配置格式，含组件身份、SHA256、15 个动态 RVA 与函数/数据字节，写入时原子替换，校验摘要防止损坏。摘要用于完整性检查，不是数字签名。
- `native/loaded_profile.h`：挂钩前再次验证 Explorer 已加载模块的 GUID、Age、时间戳、大小、模块类型、区段与函数字节；虚函数表首项必须指向本组件的可执行区段。
- `overflow_binding.inc`：修改 ItemsSource 前验证原始图标集合、元数据成员及可读取的图标信息。Taskbar.View 方案优先按集合找到列表，SystemTray 方案优先按模板名称查找，最终都要求同一原始图标集合。

原生核心为 v5，命令消息与状态属性升级为 v2；新增命令值 6：未启用返回 0，尚未展开返回 2，界面校验通过返回 1，结构拒绝返回 -13。地址校验通过后先安装观察面板的挂钩；界面校验通过后才改变图标列表，发现结构拒绝后宿主会停止并恢复托盘。

旧固定地址表移入 `tests/native/known_symbols_26200.h`，仅作已知版本回归基准。正式代码不再包含它。既有 `docs/supported-module.json` 是历史基准记录，非适配白名单。

独立原生测试（不挂钩 Explorer，不执行系统 DLL 入口点）：

```powershell
pwsh .\scripts\Test-Adaptation.ps1 -Module 'C:\Windows\SystemApps\MicrosoftWindows.Client.Core_cw5n1h2txyewy\Taskbar.View.dll' -CacheDirectory '.\build\symbol-test-cache' -CompilerRoot 'D:\llvm-mingw' -AllowDownload
```

测试比较已知基准地址，并验证 PDB 年龄/GUID、组件时间戳、模块分支、缓存格式、字节指纹、越界地址及代码/数据区段错误均被拒绝；二次解析必须支持离线缓存。跨版本测试使用两份真实 Taskbar.View.dll（2126.8901.10.0、2125.30601.0.0），未把旧组件替换到系统中。发布包包括符号辅助 EXE，但不包括微软 PDB、机器适配缓存或个人配置。

## 0.4.1 屏幕与 DPI 布局

- `src/app/app.manifest` 声明 Windows 10/11 兼容；`app.config` 启用 .NET Framework 4.8 的 PerMonitorV2，入口不再提前调用系统 DPI 模式的 SetProcessDPIAware。构建、更新、发布脚本均携带 `TrayFolders.exe.config`。依据：[微软 WinForms 高 DPI 文档](https://learn.microsoft.com/en-us/dotnet/desktop/winforms/high-dpi-support-in-windows-forms?view=netframeworkdesktop-4.8)。
- 先暂停窗体布局，构建完全部页面后统一缩放；标题使用 `HeadingLabel` 跟随窗体字体，避免显式字体在跨屏后维持旧大小。
- 按钮使用 AutoSize 和最小尺寸；文字行、操作行按内容布局，列表与规则输入区分配剩余空间。列表列宽自动适应可用宽度。
- `DisplayLayout` 在初次显示、跨屏、DPI 和系统分辨率变化时，将窗口限制到当前显示器工作区；`PageViewport` 保持可操作的页面最小尺寸，低分辨率与高缩放组合通过滚动访问全部按钮，不压缩文字。
- `DisplayLayoutTests` 在屏幕外向隔离窗体发送 WM_DPICHANGED，检查 100%、125%、150%、200% 及返回 100% 时的文字边界、标题缩放、列宽、滚动可达性；另覆盖 1366×768、1920×1080、2560×1440、3840×2160、3042×1763 的窗口尺寸和缩放组合。检查四个页签及图标选择弹窗，并输出 PNG 与 `display-checks.txt`。这些是模拟窗口/DPI 测试，不改变系统分辨率，也不等同于在所有实体显示器上实测。
- 本次仅修改管理界面及发布流程，原生 v5 分组核心保持原二进制。

分辨率测试中，超过测试机窗口跟踪尺寸上限的 4K 等场景，使用指定像素尺寸的实际根布局画布渲染；报告标记为 content canvas，其余标记为 window。低分辨率场景使用实际窗口，并逐一滚动到按钮验证可见范围。
